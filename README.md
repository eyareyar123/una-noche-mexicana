# Una Noche Mexicana · ערב מקסיקני

A Hebrew (RTL) invitation site for a private Mexican dinner: date and place, a centered fine-dining menu with hand-drawn dish sketches, and an RSVP that arrives as a **WhatsApp message to you**.

**Fully static.** No server, no database, no accounts, nothing to pay for. `npm run build` produces a folder of plain HTML, CSS and JS that any free static host can serve.

---

## Everyday use

| I want to… | Do this |
| --- | --- |
| Change the date, time, address, info or font | Edit `src/content/site.ts` |
| Change the menu (add, rename, hide, reorder dishes) | Edit the `menu` list in `src/content/site.ts` |
| Receive RSVPs on my phone | Set `hostWhatsApp` in `src/content/site.ts` (digits only, e.g. `972501234567`) |
| Keep kitchen notes (recipes, shopping, reminders) | Edit `private/kitchen-notes.md`. This file is **never published**. |
| See my changes | `npm run dev` → http://localhost:3000 |
| Publish an update | Commit and `git push`. GitHub rebuilds and republishes the site in about a minute. |

### Running locally

Requires Node.js 20.9 or newer.

```bash
npm install
npm run dev
```

### How RSVPs work

A guest fills in the same form as before: name, coming or not, dietary needs, comments. When they press **שליחת אישור בוואטסאפ**, WhatsApp opens with a ready-made message, for example:

```
🌮 Una Noche Mexicana · יום שישי, 13 בנובמבר
*אישור הגעה*

שם: דנה לוי
מגיע/ה: כן! ¡Sí!
הגבלות תזונה / אלרגיות: טבעונית
```

The guest presses Send, and the answer arrives in your WhatsApp. Messages are your guest list; there's a small table at the bottom of `private/kitchen-notes.md` if you want to keep track there.

- **If `hostWhatsApp` is empty**, WhatsApp asks the guest who to send the message to. Set your number so it goes straight to you.
- The guest's answer is remembered **on their own device**. When they come back they see "¡Hola de nuevo!" and can send an update; the form is prefilled, and the message is marked *עדכון לאישור ההגעה*.
- `rsvpOpen: false` replaces the form with a "registration closed" note.

### Images

Each dish can use a built-in sketch (`/sketches/nachos.svg`, `corn`, `pico`, `cabbage`, `fish`, `asado`, `vegan`, `guacamole`, `avocado`, `aioli`, `toppings`) or your own photo. To use a photo, put the file in `public/photos/` and write `image: "/photos/my-dish.jpg"`. The same goes for `heroImage` (the photo inside the arch on desktop). The sketches are generated by `npm run sketches` (`scripts/generate-sketches.mjs`).

### Fonts

Set `fontTheme` in `src/content/site.ts`. Every option was checked in the browser to render real Hebrew glyphs:

| `fontTheme` | Headings + body |
| --- | --- |
| `classic` | Frank Ruhl Libre + Assistant |
| `chef` | Bellefair + Assistant |
| `modern` | Heebo throughout |
| `editorial` | David Libre + Rubik |
| `cantina` *(current)* | Suez One + Rubik |
| `noto` | Noto Serif Hebrew + Noto Sans Hebrew |

## Publishing (GitHub Pages, free)

**Live site:** https://eyareyar123.github.io/una-noche-mexicana/
**Repository:** https://github.com/eyareyar123/una-noche-mexicana

It works the same way as the Moodle assignment tracker: every push to `main` runs `.github/workflows/pages.yml`, which installs, builds (`npm run build`), checks the build (`npm run check`), and publishes `out/` to GitHub Pages.

```bash
git add -A
git commit -m "Update the menu"
git push            # live about a minute later; progress shows under the repo's Actions tab
```

To try the production build locally first:

```bash
npm run build      # creates the out/ folder
npm run check      # verifies the build (see below)
npm run preview    # serve out/ at http://localhost:4173
```

On GitHub the site lives under `/una-noche-mexicana/`. The workflow sets `PAGES_BASE_PATH` for that, and images in `site.ts` get the prefix automatically. Locally the site is at the root.

`npm run check` confirms that:
- the site exported as Hebrew RTL, with the menu on the page;
- the RSVP goes to WhatsApp, and no server calls are left;
- **no line of `private/kitchen-notes.md` appears anywhere in `out/`**, and the `private/` folder isn't copied into it;
- every image referenced on the page exists.

### What's public

Everything in `src/content/site.ts` is published, including the address, the entry code in `additionalInfo` and your WhatsApp number. Anyone with the link can read it, and so can anyone browsing the **public** GitHub repository. `private/` (kitchen notes) and `data/` are git-ignored and stay on your computer. The site is marked `noindex`, so search engines shouldn't list it.

## Project layout

```
src/content/site.ts        ← all event details and the menu (edit me)
private/kitchen-notes.md   ← private kitchen notes (never published, git-ignored)
src/app/                   page, layout, fonts, global styles
src/components/public/     Hero, Menu, RSVP form, Details, Footer
src/lib/                   content loader, font pairings, date formatting, sketch helpers
public/sketches/           hand-drawn dish illustrations
scripts/                   serve (preview), check-static, generate-sketches
```

**Stack:** Next.js 16 with static export (`output: "export"`), TypeScript, and Tailwind CSS v4. Fonts are self-hosted by `next/font`.

> **OneDrive note:** if a build fails with an `unlink` / `EPERM` error inside `.next`, OneDrive was syncing the build cache. Delete the `.next` folder and run `npm run build` again.

> The old `data/` folder (the SQLite database from the server version) is no longer used. Its contents were moved into `src/content/site.ts` and `private/kitchen-notes.md`; it held no RSVPs. You can delete it.
